HOW DATA ERRORS CASCADE INTO PROCUREMENT DISASTERS

Recipe Error (5%)
If Cheese quantity in recipe is 150g but system shows 142g (5% off):
→ For 10,000 pizzas: System recommends 1,420 Kg | Actual need: 1,500 Kg → 80 Kg SHORT
→ At ₹400/Kg = ₹32,000 variance per order cycle. Multiplied across all SKUs = Lakhs/month

UOM Mismatch (gm vs Kg)
If one record says '250' (gm) and another '0.25' (Kg), system adds them:
→ Computed need: 250.25 Kg | Actual need: 0.50 Kg → 500x over-procurement
→ Perishable inventory = 100% wastage. Single incident can cost ₹1–5 Lakhs

Stale Kitchen Stock Data
If kitchen stock is not updated (outlet doesn't do daily stock-take):
→ System assumes 0 stock. Recommends full replenishment.
→ Kitchen already has 3 days of stock = excess order, wastage, blocked working capital

Missing Lead Time
If lead time for Cheese is unknown (assumed 0 days):
→ Procurement order placed day before shortage
→ Vendor cannot deliver in time → Stock-out → Kitchen shut down / revenue loss

Duplicate SKU Names
If 'Margherita Pizza' and 'Margherita Pz' are two records:
→ Sales history is split → Forecast for each = ~50% of actual demand
→ Both forecasts are wrong → Under-procurement for both variants → Stock-out


--- Slide 6 ---

Module Logic & Calculation Framework
How each module computes its output




M1
Sales Aggregation

Formula:  Daily Sales = Σ (Order Qty × SKU) grouped by [Date × SKU × Location × Brand]
Output: Clean Demand History
Requires: SKU deduplication, null date handling, channel separation



M2
Forecasting Engine

Formula:  Forecast(t) = Base × Trend Factor × Seasonality Index × Growth% × Event Multiplier
Output: SKU × Location × Horizon Forecast
Driven by: 6-month history + day-of-week + festival calendar + growth assumption



M3
Internal Supply Planning

Formula:  Replenishment = Forecast Demand + Safety Stock − Available Kitchen/Outlet Stock
Output: Kitchen-level replenishment requirement
Safety stock policy must be defined by planning team per SKU category



M4
Recipe Explosion

Formula:  Ingredient Demand = Σ (Forecast Units × Recipe Qty per Ingredient) × Yield Factor
Output: Total RM + PM requirement in standard UOM
⚠ Highest risk module — recipe errors directly multiply into procurement errors



M5
Warehouse Planning

Formula:  Net Warehouse Requirement = Total Ingredient Demand − Current Warehouse Stock
Output: Ingredient-level shortage / surplus report
Stock adjustments and GRN accuracy in SupplyNote is critical here



M6
Procurement Engine

Formula:  Procurement Qty = Net Requirement + Safety Stock − Open PO Qty  [rounded up to MOQ]
Output: Supplier-wise purchase recommendation
Lead time check: if delivery < lead time days, trigger URGENT flag automatically
